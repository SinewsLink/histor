# CLAUDE.md: working on SL Histor (this repo)

**What this is.** SL Histor by SinewsLink: independent, verifiable evidence of what AI agents did, who approved it, and what it truly cost. This public repo is the open layer: the Histor receipt spec, schemas, reference verifier, web verifier, signer, MCP proxy, Claude Code hook and CLI. Apache-2.0.

**Names.** Brand: "SL Histor". Repo: `SinewsLink/histor` (the org already says SinewsLink, so no `sl-` prefix). npm: `@sinewslink/histor-core`, `-mcp-proxy`, `-claude-hook`, `-cli`. CLI binary: `histor`. Config dir: `.histor/`. Never reintroduce "Witness", "sl-witness" or "sl-histor" names.

**Layout.**
- `packages/histor-core`: zero runtime dependencies. Canonicalization (RFC 8785), commitments, Ed25519 seals, hash-chained ledger, Merkle batches (RFC 9162), verifier, cost engine, scanners, policy and approvals, signer, Agent Receipts interop.
- `packages/mcp-proxy`, `packages/claude-code-hook`, `packages/cli`: thin layers over core.
- `spec/`: the Histor receipt spec v0.1, JSON Schemas, signed examples, conformance vectors (positive and MUST-reject).
- `web-verifier/`: generated by `scripts/build-web-verifier.js` into `packages/cli/assets/verifier.html`. Never hand-edit the output.
- `docs/`: edge-case checklist, compliance and OpenTelemetry mappings, integration guide.
- `examples/goose-crash-test/`: reproducible goose crash-and-redispatch test (`run.sh`).
- `.claude/skills/`: `histor-integration-builder` (new emitters) and `histor-spec-steward` (spec changes). Use them.

**Commands.** `npm install` · `npm test` (33 tests plus a benchmark gate) · `npm run demo` · `npm run build` (then `git diff --exit-code web-verifier packages/cli/assets` must be clean, as CI checks it) · `npm run vectors` · `npm run examples`.

**Rules that must not break.**
1. Never put raw tool arguments, outputs, prompts or secrets in a receipt. Use `commit()`.
2. Money is decimal strings and BigInt math. Never floats.
3. The proxy and hook always forward traffic, even when evidence fails. Only high-consequence calls fail closed, and only by policy.
4. Histor is evidence, not enforcement. It never sits inline in model traffic.
5. Spec or schema changes go through the spec-steward skill: schema, spec text, examples, vectors, tests, checklist and CHANGELOG in one change.
6. Export to W3C Verifiable Credentials must keep working. The third-party vectors in `packages/histor-core/vendor/agent-receipts/` must keep passing byte for byte; that folder holds upstream test-only key material, not a leak, and its credit in NOTICE is a licence requirement, so never remove it.
7. No code copied from Enlil (BSL licence). Ideas only. Any Apache code borrowed gets credited in NOTICE.
8. Every behaviour change ships with a test. Conventional commits, signed off (`git commit -s`).
9. Positioning: describe Histor by the open standards it implements (IETF RFCs, MCP, W3C VCs, OpenTelemetry once the exporter ships). Do not name or link small third-party agent-receipt projects in README, spec prose or docs; credits stay in NOTICE only.

**Not in this repo.** Pricing, customers, strategy and the commercial product (ledger server, approvals app, auditor portal, framework packs, invoice adapters) live in SinewsLink's private repos. Never copy anything from them into this public repo.

**Releasing to npm.** Publish `@sinewslink/histor-core` first, then the other three (they depend on it). `npm publish --workspace packages/histor-core`, then the same for `mcp-proxy`, `claude-code-hook`, `cli`. Bump all versions together and add a CHANGELOG entry.
